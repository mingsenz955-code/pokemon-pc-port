# 0.2.77 向阳村支线与解救乘龙主线

基于 main/c77c89b，接续 0.2.76 出口修复。此次将嘉娅任务与小丑团主线串起来检查，不以单页可打开代替剧情可完成。

## 已复现的问题与原版依据

### 嘉娅交宠

干净存档里单纯接受嘉娅任务未复现卡住；持有喇叭芽、接取后再次对话交付时，可以确定复现：costtaskitem 把宠物种类 ID 当成背包道具扣除，报“所需道具或货币不足”，runtime_error 随后阻止行走和剧情。

原 PlotEventItemCostTaskItem::begin（0x2f6e80）过滤宠物交付条目并调用 showChoicePetUi，选择后再扣除。对应 MultipleChoicePetUI、MultipleChoicePetItemUI，原列表调用 getPetListByKid，确认事件传递 UID 列表；不是自动删除任意一只宠物。

新增 task_costs / task_handover，按原页面选择具体 UID，再在事务中扣除宠物和道具；支持银行宠物、多种宠物、多数量、取消和存读档，排除试用宠物。重复 UID、数量不符或资源不足均不留下部分扣除；取消后可继续地图和对话，不伪造提交或奖励。主线 costtaskitem 的 mtask 是当前任务标志，不能当作任务 ID。

### 剧情区域没有触发

向阳村 11501（解救乘龙）完全位于 11502（跟踪小丑团）内部。此前直接取 TMX 中首个相交对象，使内层区域永远无法触发。此前对此顺序的判断和测试是错误的，本轮已更正。

核对原 VillageMapControler 构造（0x2db144）、createAreaSprite（0x2de4ec）和 getAreaSpriteAtTileCoord（0x2d8eca）：区域保存在整数 unordered_map，默认请求 10 桶，实际初始质数 11，按 hash 链遍历。新增 area_order 恢复桶内插入、碰撞和再散列顺序，而非 XML 顺序。全部原地图最多 14 个区域，本资源集只需 11→23 的扩容范围。

已就绪但遗漏区域剧情的旧存档，在实际走到对应主线目标区域时，用原计数前状态匹配一次原触发；保留真实就绪状态和计数，不远程提交，不重复执行已完成事件。

### 后续仍会卡住的两个通用问题

- 原 giveitem 允许负数，21 条负数条目用于交回/清除剧情物品。旧 grant_many 拒绝负数，解救乘龙后交回 270045 就会停住。现在按原有符号增减，清除数量不超过持有量，同一指令事务化；奖励弹窗只展示正数。
- pEvent115003 第 64–68 步会在地图上继续对话、移动焦点并自动关闭。旧版把它按普通菜单暂停剧情，areamapmove 也只改数字不刷新地图。现在仅对有明确 auto=1 关闭指令的原脚本保持地图剧情运行，叠加原 DialogUI/头像，响应点击、更新地图焦点并按脚本关闭；普通柜员菜单仍等待玩家操作。
- 原事件里另有 18 个文件含重复编号，但没有跳转到这些重复编号。旧加载器一律拒绝，导致后期剧情无法启动。现在按原数组顺序保留这些指令，仍拒绝真正有歧义的跳转目标，未删改原剧情内容。

窗口版的未知 Tk 回调异常会记录到存档目录的 game-errors.log（最多保留当前及前一份），包含地图、事件和指令位置。日志用于定位未知问题，不代表自动跳过失败剧情。

## 验证

新增 check_sunshine_quests 十项，包括：

- 嘉娅实际对话、接取、取消交付、选择具体喇叭芽、奖励和完成状态；只移除选中的宠物，奖励一次。
- 银行宠物、排除试用、交付页实际存读档续接；物品不足提示可以通过 Esc 退出且不提交任务。
- 原向阳村入场 → 跟踪区域 → 内层解救区域 → 实际战斗获胜 → 两名 NPC 离场 → 交信 → 获得乘龙 → 地图对话/定位旧都城 → 自动关闭 → 出海到地图 201，主线进入 17。战斗用隔离存档的原预设 201，调用实际普通攻击取得胜利，没有注入胜利状态。
- 全部 155 条主线、170 条支线任务交付配置；所有原负数 giveitem 指令；18 份重复编号脚本可以加载；所有原地图的区域容器顺序构造；旧的就绪区域计数恢复原剧情。

另有实际 Tk 定时刷新检查：地图打开期间持续刷新，点击原对话可更新焦点，并能执行自动关闭。

另执行支线派发、任务计数、剧情移动/镜头、老人传送与左出口、孵化教学、单窗口、原页面、柜员生命周期、零奖励任务、捕捉布局和接任务检查。修正两个旧检查入口：孵化蛋现在点击即放入，不能再调用已经返回上一页的 use_Button；接任务使用实际原卡片与回调，不检查已移除的独立窗口字段。

日志和代表界面在 outputs/verification/sunshine-story。全部检查使用临时存档，未修改玩家真实进度，未关闭现有游戏。Windows 包另用隔离存档启动检查。
