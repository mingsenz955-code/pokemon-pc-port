# 0.2.74 老人赠蛋后的孵化教学阻塞

基于主分支 d33072a（0.2.73），保留原抽宠演出、骑乘和柜员页面修复。

## 原因

这条问题可以用原 pEvent5905001.json 完整复现，不是单纯帧率低：

1. 第 6 步 openui 后紧跟按钮教学，宿主却一直等待关闭孵化屋才推进。关闭后，教学需要的按钮已经不在画面中。
2. 剧情使用 putIn_Button_1、check_Button_1、takeBack_Button_1、hatchRoomChooseItem_250001，而宿主重复卡片只暴露带路径的按钮和背包选择操作，缺少对应关系。手动孵化不会自动完成这些剧情步骤。
3. 演出确认按钮尚未生效时，回调返回空值，宿主仍把教学当成完成，导致提前切换到领取引导。
4. 孵化任务结束后的 draw_Button 被 lottery_ui 的 runtime.running 条件拒绝，剧情继续等待另一个未打开页面的按钮。

此前 check_counter_hatching 覆盖的是孵化和柜员操作，没有从原教学脚本开头走完这条链，遗漏了这个阻塞。

## 修复

- 仅对紧随 button 的 openui，在页面打开后继续执行教学；普通柜员 openui/closeui 的等待规则保留。
- 绑定原一基数孵化位名称、蛋选择名称和加速孵化按钮。选择蛋会直接放入，保留普通背包的选择/使用行为。
- 按原第 12 步文字和参数，仅给教学蛋 250001 一次免费加速；生成、孵化统计和领取仍走实际事务。普通孵化仍付费，重复免费请求回滚。
- 确认回调明确返回 False 表示演出未结束，宿主不会推进教学。孵化教学期间不响应其他位置的按钮或提前 Esc 关闭，防止将运行中的脚本留在没有页面的状态。
- 原抽宠引导可以在当前教学剧情中打开抽宠页面；其他运行中的剧情仍不允许随意打开。
- 旧存档中，若此教学仍在前面的按钮步骤，但实际第一个孵化位已有对应蛋或已孵好的宠物，则从实际进度重建页面并继续检查/领取；不重新扣费、生成宠物或伪造提交任务。新版本也记录教学领取 UID，支持领取后读档继续。没有对应实际进度证据时不会直接补发宠物或完成任务。

## 验证

新增 tools/check_hatch_tutorial.py，复用八项柜员孵化检查并增加三项：

- 实际原剧情和按钮链：打开孵化屋 → 放蛋 → 条件页 → 免费孵化 → 提前确认无效 → Tk 定时演出 → 正常确认 → 领取和奖励框 → 关闭 → 告别 → 任务提交 → 抽宠引导。校验任务、开放状态和宠物数量，捕获 Tk 回调异常。
- 保存旧版已孵好但卡在最前面引导的状态，再实际读取，恢复到领取；同一 UID 只入包一次，金币不再扣除。
- 免费教学只能执行一次，拒绝重复时不留下部分改动，普通金币孵化仍按原表收费。

同时运行孵化条件、原经验石教学、全屏/金币/音频、柜员页面生命周期、抽宠和单窗口回归。所有存档指向临时目录，没有改玩家实际存档，没有强制关闭正在玩的游戏。发布包用独立存档进行启动检查。

本轮针对孵化教学的确定性阻塞，不意味着全游戏任意卡顿均已消除。未做原 Android 同屏全流程录像验收；既有动画混合、后期剧情等边界继续见 RESTORATION_REMAINING.md。
