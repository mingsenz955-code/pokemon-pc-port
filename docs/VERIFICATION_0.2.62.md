# 0.2.62 进化、登录、寻宝、开箱与成就修复

本轮基于 PR16，合并 origin/main/89ff3af 的 PR17 骑宠菜单修复。旧包和玩家存档均保留。

## 修复

- 去除 UI 的 `bg_Panel` 半透明矩形遮罩，避免面板周围出现一整块变暗的矩形。纸张自身阴影和原特效素材仍由原资源呈现。
- 进化条件页撤掉深色 Tk 列表，改用 ConditionItemUI 展示实际等级/材料数量，补前后宠物待机预览。等级或材料不足时不能扣物品；成功后显示 PetEvolutionEffectUI 的实际前后属性和目标宠物。
- 放大镜页替换爱心占位资源，使用 Item 220007 的真实图标、持有量、藏宝图线索；文字增加内边距。
- 没有进行中的藏宝图时，放大镜入口进入原 TreasureBuyConfirmUI；显式传入的原 Treasure ID 保留，不带参数的首次入口选择表中 ID1。ID1 价格为 5 徽章，附赠 3 个放大镜，线索在镇东树林。购买后先展示实际获得道具，再回到线索页。
- 开箱页使用 ChestItem 的实际钥匙图标和需求数量。需求 x1 不再被“当前拥有钥匙数”覆盖；没有钥匙不扣箱，成功开箱显示真实奖励。
- 登录后若今天已领，默认选中已领取的那天；下一份显示“明日可领”，更后日期显示第几天开放。已领取、可领取、未开放分别展示，重复点击不重复发奖。
- 未来/已领取的登录卡片不播放领取粒子。面板有自己的动画计时，打开时不再反复绘制被捕获背景覆盖的地图；图像上传改为 PIL 到 Tk 单向上传，取消每帧从 Tk 读回像素。
- 粒子轨迹缓存每个原 1/60 秒积分步；无径向/切向加速度时求等价闭式和。颜色查表缓存、单次 RGBA 查表、加色混合仅处理粒子实际像素边界，减少主线程开销。动画仍按真实时间推进。
- 成就条件类型 1 接入指定宠物、属性系、星级、品质、天赋数、等级和去重条件。修正旧实现把星级误当品质。已有皮卡丘可以领取成就 101；每个成就只领取一次。

## 原版依据

- AchievementItemCollectPet::process 0x2bf7d8 按表顺序读取七项条件，再调用 PlayerDataManager::getPetCountByConditions 0x330cc2；第 3 项是物种表星级，第 4 项才是个体品质。
- Achievement 101 的 conditions=`100079,-1,-1,-1,-1,-1,0`，表示当前携带/银行内的皮卡丘，不是一个未实现的任意类型。
- TreasureMapUILayer::buyButtonRespond 0x3c1598 使用显式 Treasure ID 的货币、价格，并判断已有藏宝图。当前补全了无图入口；未把默认第一张图伪称为已复刻原完整随机/区域分配规则。
- Item 220007.texture=`itemIcon_2_7.png`；ChestItem 210001 的 costIds=240001，钥匙 Item.texture=`itemIcon_4_1.png`。
- Evolution、ConditionItemUI、EvolutionConditionUI、PetEvolutionEffectUI，以及 ContinuousLogin/ContinuousLoginItemUI 来自本地恢复的原数据/CSB。

## 验证

新增 check_restore_followups.py 七项实际宿主回调测试：多种页面四角不变暗、皮卡丘成就只领取一次与星级/品质区分、登录已领/明日状态、进化条件失败与成功结果、购买图和附赠道具、箱子钥匙实际消耗、动画上传不从 Tk 读回像素。

本轮 17 组回归通过，包含骑宠菜单、上一轮单窗口流程、任务、背包全表、原页面、战斗点击/结算/动画/运行时、特殊特效、PR13 review、寻宝、战斗成就和通用回归。末次粒子混合优化后重新通过新流程七项与背包十六项检查。

登录采样中暖帧约 20–32ms，冷帧约 55ms；该数值是本机独立动画回调样本，不等于所有页面或机器稳定 60fps。机器结果见 outputs/verification/followup-results.json 和 followup-login-times.json。
